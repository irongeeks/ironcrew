# OctoOffice v2.4.0 Release Notes

- Release date: 2026-03-30
- Scope: Office map v2 with full spatial overhaul, dynamic pack input parameters, pack artifact collection and decision enrichment, token usage tracking with per-task budget enforcement, and a broad design system audit.

## Highlights

### 1. New Office Map v2

- Completely replaced the office map with a redesigned layout covering 7 department offices (`Office_1` through `Office_7`), each with proper seat zones.
- Added a dedicated `CEO_seat` position — the CEO no longer falls back to generic seats.
- Server room added with a dynamic label rendered in VT323 font alongside all other room labels.
- Corridor/hallway system introduced: idle agents now wander hallways instead of the break room, producing more realistic office movement.
- Auto-pathfinding connects isolated walkable regions through the shortest wall passage automatically; agents respect walls and furniture stays solid.
- Improved direction variety for agent movement; pathfinding fixes address door passthrough and wall-casing edge cases.

### 2. Pack Inputs — Dynamic Optional Inputs

- Packs can now declare optional input parameters in `pack.yaml` under a new `input:` section.
- `PackInputsSection` component renders dynamic input fields in the task creation dialog, replacing the previous hardcoded `sceneCount` approach.
- `UPDATE_INPUT` action added to pack editor state; `PackMetaPanel` Inputs tab is editable in Editor and Builder modes.
- Input values reset automatically when the active pack key changes (stale closure bug fixed).
- `zh` locale support added for input labels.
- All existing packs benefit from the system with zero changes required; packs without an `input:` section behave identically to before.

### 3. Pack Artifact Collector

- New `pack-artifact-collector` helper aggregates terminal phase outputs across a pack task run.
- Enables downstream phases and report generation to access prior phase output without manual path threading.
- Collector writes outputs to `workspaces/<task>/artifacts/<phase>.terminal.txt`.

### 4. Decision Inbox Enriched with Pack Artifact Context

- When an agent requests a human decision, the decision notice now includes relevant pack phase artifacts collected by the artifact collector.
- Approvers receive richer context — prior phase outputs are surfaced inline — enabling more informed approval decisions.

### 5. Pack Task View Improvements

- Task logs are shown as a fallback in the Protocol tab when no meeting minutes exist for a pack task.
- Pack terminal artifacts are now used as the report body for pack tasks, producing richer task summaries.
- Diff modal now renders full-screen via a React portal, eliminating clipping inside nested scroll containers.
- Icon buttons made more visually prominent across the task view.

### 6. Worktree Map Rehydration from Disk

- On server startup, the in-memory worktree map is now restored from disk-persisted worktree state.
- Prevents task resumption failures that occurred after a server restart when in-flight tasks had active worktrees.

### 7. Token Usage Tracking with Per-Task Budget Enforcement (#18)

- Tracks prompt and completion token usage per agent per task.
- Configurable budget thresholds; per-task budget enforcement prevents runaway agent spending.
- Token usage bars are visible on agent cards in the Agent Sidebar Panel.
- New API endpoints expose per-agent and per-task token breakdowns (see API and Behavior Notes).

### 8. Design System Audit

- Removed dead `part06.css` file from the CSS split.
- Fixed 90+ UI violations covering spacing, colour, and depth inconsistencies identified against the design token system.

### 9. Large File Splits and Codebase Health

- Oversized modules split into focused files to improve import boundaries and maintainability.
- Dead code removed across the frontend and backend.

## API and Behavior Notes

- Pack YAML: new optional `input:` section for declaring pack-level input parameters; existing packs are unaffected.
- Token tracking: `GET /api/ops/agents/:id/token-usage` — per-agent token stats.
- Token tracking: `GET /api/core/tasks/:id/token-usage` — per-task token breakdown by phase and agent.
- Artifact collector output path: `workspaces/<task>/artifacts/<phase>.terminal.txt`.

## Compatibility Notes

- Office map v2 replaces `Officenew.json`; seat naming conventions are unchanged (`Office{N}_seat{M}`, `CEO_seat`) — no database migration needed.
- Token tracking is additive; existing tasks show zero usage until agents run new subtasks under the updated runtime.
- Pack YAML `input:` section is optional; packs without it behave identically to before.
