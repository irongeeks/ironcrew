# IronCrew 0.2.0 — 2026-09-05

Die neue Firmenverwaltung für Modell- und Provider-Freigaben erweitert die frühe
Produktreihe von 0.1.0 auf 0.2.0.

- Owner können erlaubte Modellfamilien und OpenRouter-Provider einschränken.
- Die zentrale YAML-Policy bleibt die verbindliche Obergrenze.
- Revisionen, Begründungen und Audit-Verweise bleiben gespeichert; veraltete
  Schreibstände werden abgewiesen.
- Deutsche Oberfläche mit Vorschau, Modellprüfung und Änderungsverlauf.
- Task-, Meeting-, Resume-, Routing- und Runner-Ausführung prüfen die Freigaben.
- Leere Providerlisten sperren OpenRouter vollständig; ein Runner darf die
  übertragene Policy nur weiter einschränken.

[Bedienung, API und genaue Grenzen](../VENDOR_POLICIES.md).

## Update

Control Plane und native Runner gemeinsam aktualisieren. Ältere Runner können die
neue Jobstruktur nicht verarbeiten. Migration 0035 ergänzt die Revisionstabelle;
ohne Owner-Änderung gelten weiterhin die zentralen Freigaben. Vor dem Update wie
üblich Datenbank, Vault, Konfiguration und private Dateien sichern.

Eine Installation auf 2.8.0 muss zuerst den dokumentierten Übergang auf 0.1.0
vollziehen. Danach funktioniert das normale Update auf 0.2.0.
[Update-Anleitung](../RELEASES.md).

Laufende externe Requests werden durch neue Freigaben nicht rückwirkend
zurückgenommen. Native Runs erhalten die Firmenauswahl beim Start. Echte
angemeldete CLI-Runs bleiben auf dem Betreiberhost zu prüfen. Dieses Release
installiert nichts auf einem Produktionshost.

## Prüfung

Die Veröffentlichung setzt erfolgreiche CI- und Plattformprüfungen desselben
Main-Commits voraus. Neue Tests decken Ownerrechte, unveränderliche Obergrenzen,
Revisionkonflikte, SQLite-Neustart, Audit-Rollback, Runtime-Durchsetzung und den
Browserworkflow mit anschließender Wiederherstellung der Testkonfiguration ab.
