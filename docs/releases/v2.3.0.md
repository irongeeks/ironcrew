# OctoOffice v2.3.0 Release Notes

- Release date: 2026-03-26
- Scope: Visual Node Editor (Visualizer + Editor modes), connector auto-dispatch, phase reset APIs, MCP client integration, observability stack, and security hardening across file operations, token handling, CSRF, SSRF, and concurrent phase advancement.

## Highlights

### 1. Visual Node Editor — Visualizer Mode

- Added a graph panel to the Tasks tab (toggle via the "Graph" button) showing a read-only phase DAG for any workflow pack.
- Built with React Flow and dagre auto-layout; phase nodes display: phase ID, capability mode badge, approval gate indicator, and artifact edges between phases.
- Approval gate indicators are prominently surfaced on nodes requiring human sign-off before execution proceeds.
- Node positions persist across sessions via `PUT /api/ops/workflow-packs/:key/positions`.

### 2. Pack Editor Completeness

- Editor mode of the Visual Node Editor is now feature-complete:
  - Phase type dropdowns for selecting node behavior.
  - Fan-out configuration panel for controlling parallel sub-phase branching.
  - `PropertyPanel` for inline editing of phase metadata without leaving the canvas.
  - YAML preview pane with save — changes are written back to the pack definition via `PUT /api/ops/workflow-packs/:key/definition`.
- Built-in packs can now be edited in Editor mode; saves automatically create a community override, leaving the shipped built-in file untouched.

### 3. Connector Auto-Dispatch, Phase Reset, and Auto-Workspace

- **Connector auto-dispatch:** The graph runner now executes `server`-mode capability phases directly through the registered connector — no agent process is spawned. Input artifacts are read from the previous phase, the connector API is invoked, outputs are saved, and the graph advances automatically.
- **Phase reset API:** Two new endpoints support targeted phase rollback:
  - `POST /api/core/tasks/:taskId/phases/:phaseId/reset` — resets a single phase to `pending`.
  - `POST /api/core/tasks/:taskId/phases/reset-from/:phaseId` — resets the target phase and all downstream phases via BFS traversal (graph order, not creation order).
  - Both endpoints stop any active agent process before mutating state to prevent race conditions.
- **Auto-workspace:** New tasks now have workspace directories created automatically based on the pack's `default_workspace` field, removing the need for manual path setup on task creation.

### 4. MCP Client Integration and API Rate Limiting

- OctoOffice now acts as an MCP client, connecting to external MCP servers over `stdio` and `sse` transports.
- Discovered MCP tools auto-register as capabilities in `ConnectorRegistry` and are surfaced in agent prompts without additional configuration.
- MCP server management routes added at `/api/ops/mcp-servers` (`GET`, `POST`, `DELETE`).
- Global API rate limiting introduced: 100 requests/minute per IP by default, configurable via environment variable.

### 5. ComfyUI TTS Capability

- Added `text2speech` capability to the ComfyUI connector using the SaveAudio node.
- Stub TTS interface added at `server/modules/workflow/tts/` as the integration point for future TTS connector expansion.

### 6. Observability Stack

- Structured logging with per-request correlation IDs across all backend modules.
- Workflow execution tracing records phase transitions, connector invocations, and agent lifecycle events.
- Performance metrics collection feeds an OTLP export endpoint compatible with Prometheus and Jaeger backends.
- Zero additional configuration required for local use; external observability backends opt in via the OTLP endpoint.

### 7. Security Hardening

- Path traversal vulnerability fixed in SSH and file operation routes.
- Token leak prevention: sensitive values stripped from API responses before serialization.
- CSRF enforcement applied to all state-mutation routes.
- SSRF prevention added for external URL fetching in connector and research pack paths.
- Race conditions in concurrent phase advancement resolved; graph-runner phase state transitions are now fully transaction-safe under parallel subtask completion.

### 8. Subtask Live-Sync and UI Improvements

- Subtask state updates now reflect immediately in the Tasks UI without requiring a full page refresh.
- Phase reset button labels clarified to distinguish single-phase reset from downstream cascade reset.

### 9. Critical Test Coverage for Core Execution Pipeline

- Unit and integration tests added for: graph-runner, artifact-bridge, phase approval flow, fan-out resolution, and hook execution.
- Coverage closes the principal gaps in the orchestration layer ahead of the connector auto-dispatch rollout.

## API and Behavior Notes

- New: `GET /api/ops/mcp-servers` — list configured MCP servers
- New: `POST /api/ops/mcp-servers` — add an MCP server
- New: `DELETE /api/ops/mcp-servers/:id` — remove an MCP server
- New: `POST /api/core/tasks/:taskId/phases/:phaseId/reset` — single phase reset to `pending`
- New: `POST /api/core/tasks/:taskId/phases/reset-from/:phaseId` — BFS downstream phase reset
- New: `GET /api/ops/workflow-packs/:key/positions` — read persisted node positions
- New: `PUT /api/ops/workflow-packs/:key/positions` — write node positions
- ComfyUI connector: new `text2speech` capability (SaveAudio node)
- Rate limiting: 100 req/min per IP; override via `RATE_LIMIT_RPM` env var

## Compatibility Notes

- Phase reset endpoints are safe to call on running tasks — the active agent process is stopped before any state mutation occurs.
- MCP integration requires explicit server configuration in Settings > Ops > MCP Servers; no MCP servers are auto-discovered from the environment.
- CSRF enforcement may affect custom API integrations that issue state-mutation requests without a CSRF token header — update clients to include the `X-CSRF-Token` header.
- Built-in pack edits are written to `server/packs/community/` as overrides; the originals in `server/packs/built-in/` remain unchanged and serve as the fallback if the community override is deleted.
