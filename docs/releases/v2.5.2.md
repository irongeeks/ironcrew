# OctoOffice v2.5.2

Released: 2026-05-07

## Overview

Small patch release that finishes the `pnpm setup` → `pnpm run setup` cleanup
that began in v2.5.1 (commit `24a1403` only patched the README) and bundles
the post-tag documentation polish from v2.5.1.

The bare `pnpm setup` command is reserved by pnpm itself for installing pnpm,
so any project script named `setup` must be invoked via `pnpm run setup`.
v2.5.1 left several internal references on the wrong command — those are now
all corrected.

## Fixed

- `pnpm setup` → `pnpm run setup` in:
  - `CHANGELOG.md` (v2.5.1 cleanup line)
  - `docs/releases/v2.5.1.md` (cleanup section)
  - `templates/AGENTS-octooffice.md` and `AGENTS.md` (orchestration-rules
    template header)
  - `scripts/setup.mjs` and `scripts/setup-wizard.mjs` (usage docstrings)
  - `server/modules/routes/ops/setup-status.ts` (error detail strings shown
    in the setup-status panel)
  - `server/modules/routes/ops/messages/directives-inbox-routes.ts`
    (OpenClaw `agent_upgrade_required` payload — `agents_only` install command
    + the absolute variant with `--agents-path`)
- `scripts/setup-wizard.mjs` non-interactive support:
  - When `process.stdin.isTTY` is false (piped, redirected, or absent stdin),
    the wizard now accepts all defaults instead of hanging silently. This
    affected CI installs, Docker provisioning, and AI-coding-agents that
    drive `bash install.sh` without a controlling terminal.
  - New `--yes` / `-y` flag for explicit non-interactive opt-in even when a
    TTY is present. Passed through `scripts/setup.sh` and therefore through
    `bash install.sh --yes`.

## Docs

- `docs/how-it-works.svg` simplified to a single linear pipeline diagram
  (carried over from `fd1f012`).

## Upgrade

```bash
git pull
pnpm install
pnpm run setup        # only required if AGENTS.md is missing the
                      # orchestration-rules block
pnpm dev
```

No database migrations required.
