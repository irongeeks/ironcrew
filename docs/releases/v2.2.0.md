# OctoOffice v2.2.0 Release Notes

- Release date: 2026-03-20
- Scope: Platform architecture overhaul introducing declarative workflow packs, typed provider adapters, and service connectors; SSH server management; complete German locale; dynamic community pack registry; and a new vertical navigation layout.

## Highlights

### 1. Platform Architecture — Declarative Packs, Connectors, Adapters

This is the largest architectural change since v2.0.0. Three new declarative layers replace the previous monolithic `buildAgentArgs` switch-case and hard-coded workflow logic.

**Workflow Packs (`server/packs/`)**

- Workflow definitions are now YAML files (`pack.yaml`) describing phase DAGs, connector bindings, input schemas, cost profiles, and QA rules.
- Loaded at startup via `pack-loader.ts` and registered in a `PackRegistry`.
- Per-phase guidance lives alongside each pack as `guidance/<phase-id>.<lang>.md` files.
- `pack-schema.ts` exports Zod schemas for all pack.yaml fields.
- Community packs dropped into `server/packs/community/<pack-key>/` override built-in packs by key — zero code changes required.

**Connectors (`server/connectors/`)**

- API wrappers for external services exposing named capabilities (e.g. `text2img`, `web_search`).
- Implement the `Connector` interface (`connector-interface.ts`) and register via `ConnectorRegistry`.
- Auto-bound from settings at server startup (e.g. `comfyui_server_url` triggers ComfyUI binding).
- Built-in connectors: ComfyUI (`text2img`, `img2video`) and web-search.
- CRUD routes at `GET/POST/PUT/DELETE /api/ops/connectors`.

**Provider Adapters (`server/adapters/`)**

- Typed, testable classes replacing the old `buildAgentArgs` switch-case.
- Implement `CliAdapter` or `HttpAdapter` from `adapter-interface.ts`.
- Registered via `createAdapterRegistry()` in `server/adapters/index.ts`.
- Current adapters: `claude`, `codex`, `gemini`, `openclaw`, `opencode`, `copilot`, `antigravity`.

**Phase Execution Modes (`capability_mode`)**

| Mode | Behavior |
|------|----------|
| `agent` (default) | LLM agent executes the phase |
| `hybrid` | Agent executes with connector guidance injected into the prompt |
| `server` | Connector executes directly — no agent spawned, input read from predecessor artifacts |

**Graph Runner**

- Drives DAG execution end-to-end: seeds subtasks from the phase DAG, advances phases when predecessors complete, invokes connectors for `server`-mode phases, and calls run-complete handlers for agent phases.
- All phase advancement is transaction-safe.
- Fixed DB interface mismatch (`prepare().run()` for real SQLite).

### 2. SSH Server Management and Remote File Operations

- New `ssh_remote` server type with `ssh_config_json` DB column (migration included).
- SSH command allowlist with validation and parsing enforced for security.
- `ServerFileBrowser` component for browsing remote file trees over SSH.
- Remote folder creation via `DashboardQuickActions`.
- SSH agent execution guidance injected automatically into agent prompts when a task targets a remote server.
- New routes: `GET/POST /api/ops/servers`, `GET /api/ops/servers/:id/files`, `POST /api/ops/servers/:id/files/mkdir`.
- New **Servers** tab added to Settings for configuring external server connections.

### 3. Complete German (de) Locale

- All remaining UI components translated to German: Chat, Terminal, Agent UI, all Settings tabs, Skills Library, Taskboard, GitHub import, office workflow pack selector, and Project Manager.
- German (`de`) is now a first-class supported language alongside EN, KO, JA, and ZH.

### 4. New Navigation Layout — Vertical Left Nav + Right Agent Sidebar

- Replaced the top-bar-only navigation with a vertical left navigation (`RetroSidebar`) + a right-side `AgentSidebar` panel.
- The office canvas now sits between navigation on both sides for a cleaner, more dashboard-oriented layout.
- Fixed agent head crop rendering that appeared in the new layout.
- Updated office view background to use the new palette tokens.

### 5. Nefesh GTM Community Workflow Pack

- First community pack shipped to demonstrate the community override mechanism.
- Includes a `ui:` section for automatic dynamic dashboard registration (labels, departments, room themes, staff cycle, avatar pools).
- Serves as the canonical template for authoring new community packs.

### 6. Dynamic Community Pack Registry

- New `GET /api/ops/workflow-packs/registry` endpoint serves a merged view of built-in and community pack metadata to the frontend.
- The pack selector, task filters, and settings dropdowns now iterate the dynamic registry instead of a hard-coded list.
- Adding a community pack and restarting the server is sufficient for it to appear everywhere in the UI.

### 7. Research Pipeline Improvements

- Model routing updated for improved phase-level provider selection.
- Depth configuration added: `quick`, `standard`, and `deep` research modes configurable per task.
- Improved prompts across all research phases.
- Fan-out/fan-in crawler phase hardened for reliability under concurrent subtask execution.

### 8. Comprehensive CI Test Suite

- Split CI workflow: unit tests, integration tests, and E2E smoke tests now run in separate jobs.
- E2E smoke tests added for video and research pipelines.
- Phase approval endpoint covered by integration tests.
- Artifact-bridge edge case tests added.
- Eliminated 401 race condition on app load; expanded E2E coverage to catch auth-timing failures.

## API and Behavior Notes

- New: `GET /api/ops/workflow-packs/registry` — merged built-in + community pack registry for UI consumption.
- New: `GET/POST /api/ops/servers` — server CRUD including the new `ssh_remote` type.
- New: `GET /api/ops/servers/:id/files` — SSH remote file browser.
- New: `POST /api/ops/servers/:id/files/mkdir` — remote directory creation over SSH.
- Pack YAML extended: `ui:` section for dashboard metadata; `capability_mode: agent | hybrid | server` per phase.
- Community packs directory: `server/packs/community/<pack-key>/pack.yaml`.
- Connector CRUD: `GET/POST/PUT/DELETE /api/ops/connectors`.

## Compatibility Notes

- Platform architecture is fully backward-compatible: existing workflow packs continue to function; the old `buildAgentArgs` paths have been migrated to adapters transparently.
- The `server` capability mode is opt-in per phase; unmarked phases default to `agent` behavior as before.
- SSH features require the `ssh2` package (already present in dependencies); no manual install needed.
- German (`de`) locale is additive — existing locale behavior for EN, KO, JA, and ZH is unchanged.
- Community pack directory (`server/packs/community/`) is empty by default; the Nefesh GTM pack is included as an example and can be removed or replaced freely.
