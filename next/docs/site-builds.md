# Reale Website-Builds und Pakete

Statische Sites werden direkt als manifestgeprüfte Dateien erstellt. React und WordPress benötigen einen tatsächlich attestierten `ExecutionPort` aus dem Linuxprofil. Ein beliebiges Objekt mit `execute()` oder eine gespeicherte `verified`-Behauptung genügt nicht. Das Profil sperrt Netzwerk, Hostdateien und Secrets. Buildausgaben verlassen die Isolation über einen begrenzten, hashgeprüften Export in ein neues Verzeichnis.

React verwendet die gepinnten Pakete React/React DOM 19.2.7. `scripts/build-site-runtime.ts` erstellt aus den installierten Lockfile-Abhängigkeiten ein lokales Laufzeitmodul samt MIT-Lizenz und SHA-256. Das Kundenpaket enthält eine bearbeitbare React-Komponente, den ausgewählten HTML-Entwurf als Daten, einen offlinefähigen Build und einen Node-26.4.0-Server. JSX erfordert einen gesondert geprüften Compiler; der Standard erzeugt JavaScript-Module mit `createElement`.

WordPress erzeugt ein Blocktheme mit `style.css`, `theme.json`, `templates/index.html` und `functions.php`. Die Struktur folgt dem [WordPress Theme Handbook](https://developer.wordpress.org/themes/core-concepts/theme-structure/). PHP-Syntax wird im versiegelten Toolchainprofil geprüft. Die getrennte Entwurfsvorschau führt WordPress nicht aus. Das fertige Theme wurde zusätzlich in einer lokalen WordPress-7.0.4-Installation mit PHP 8.3.6 und MariaDB 10.11.14 aktiviert; alle 3.945 veröffentlichten Kerndatei-Prüfsummen stimmten. Startseite, Theme-CSS und REST-API antworteten erfolgreich. Die verwendete Version ist über die [offizielle Releasebeschreibung](https://wordpress.org/news/2026/08/wordpress-7-0-4-release/) nachvollziehbar.

Der Paketdownload unter `/api/v1/artifacts/{id}/package` prüft sämtliche Dateien gegen das unveränderliche Manifest, erstellt eine deterministische `.tar.gz` und liefert Archiv- und Paket-SHA-256 in Antwortheadern. Die separate Vorschau verwendet dieselben Manifestbindungen. React-Skripte laufen dort mit opaker Sandbox-Origin; Zugriff auf Elternseite und Netzwerk bleibt gesperrt. Aktive Inhalte erhalten keinen Zugang zur CEO-Sitzung.

Nachweise: `scripts/site-build-lab.ts` führt beide Builds in der Linux-VM aus, `scripts/verify-site-browser.ts` öffnet deren tatsächliches React-Archiv im Browser, und `scripts/wordpress-runtime-lab.py` validiert das Theme in einer wegwerfbaren Linux-Testinstallation. Ergebnisdateien liegen unter `docs/test-evidence/isolated-site-browser.json` und `docs/test-evidence/wordpress-runtime/`. Keine dieser Prüfungen veröffentlicht eine Kundensite.
